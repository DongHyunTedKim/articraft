0포크 운영 원칙

이 포크는 upstream(로컬 우선 3D 생성 하네스)을 OIC TB 통신국사 디지털트윈 자산 공장으로 특화합니다. 충돌을 최소화하는 4원칙:

  • 수정은 최소 seam — upstream 파일 안의 변경은 몇 줄짜리 훅에 그친다 (16개 전부 소규모, 최대 +14줄).
  • 신설은 무충돌 경로 — 포크 고유 로직은 upstream이 만들 리 없는 경로(domain/, qc/, scripts/, sdk/_docs/domain/)에 둔다.
  • seam은 테스트로 가드 — 병합 후 uv run --group dev pytest tests/fork -q가 깨지면 재적용할 seam을 알려준다.
  • 데이터는 git+LFS 추적 — upstream은 data/ 전체를 무시하지만, 포크는 확정 레코드를 자산으로 보존한다.

6Git·LFS 설정

파일내용
.gitattributesdata/records/** filter=lfs — 추적 레코드 전체가 LFS 경유
.lfsconfigfetchexclude = data/records/** — 클론 시 LFS blob 다운로드 생략(온디맨드)
주의: 이 조합(fetchexclude × pre-commit stash) 때문에 checkout/stash가 레코드를 포인터로 바꿔놓는 사고가 반복됐음. 복구는 git lfs checkout 금지 — .git/lfs/objects에서 직접 복사 후 git add 정규화.

7유지보수 가이드 — upstream 병합 절차

기능 추가나 upstream 병합 때 이 순서를 따르면 포크가 깨지지 않습니다:

  • ① 병합 후 즉시 uv run --group dev pytest tests/fork -q — 실패 메시지가 재적용할 seam(현재는 cost.py)을 지목.
  • ② 재생성 파일은 손병합 금지 — designer_system_prompt_*.txt 6종은 spec.py에서 재생성, uv.lock은 uv lock.
  • ③ 무마커 seam 15개 육안 확인 — 특히 spec.py·workspace_docs.py·sdk/_profiles.py·cli/main.py의 1–14줄짜리 배선은 충돌 없이도 사라질 수 있음. 이 문서 §1의 표가 체크리스트.
  • ④ data/를 절대 blanket-ignore/삭제하지 않기 — .gitignore seam(A-5)이 병합에서 되살아나지 않는지 확인.
  • ⑤ LFS 포인터 검사 — 병합·stash 후 grep -rl "git-lfs" data/records | wc -l이 0인지.
