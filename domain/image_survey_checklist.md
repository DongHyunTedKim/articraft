# 장비 사진 → 생성 요소 추출 체크리스트

참조 사진에서 생성 프롬프트 요소를 뽑을 때의 표준 판독 순서.
2026-08-03~04 세션(4종 + 레이싱 바 8종 + FortiGate + 7010T-48 개선)에서
실제로 결함을 잡아낸 항목들로 구성. 프롬프트 작성 전에 순서대로 훑는다.

## 공통 — 모든 랙마운트 장비

1. **골격**: U 높이, 몸통 폭 vs 귀 포함 폭(EIA 482.6), 깊이 단서.
   귀 형태 — 나사홀 **개수**(FortiGate 3→2 교훈), 노출 판 vs 래치 커버(DL380 교훈).
2. **전면 구획**: 좌→우 존 분할과 각 존의 **폭 비율**. 눈대중 말고 도면·사진의
   기준선과 대조 (DL380 "드라이브 블록이 절반 점유" 교훈 — 실물은 균등 3분할).
3. **반복 요소 그리드**: 포트/베이 개수·행×열·그룹핑·피치. 넘버링 규칙
   (홀수 위/짝수 아래, ▲▼ 마커, 그룹당 라벨 스트립 위치).
4. **커넥터 개별 실루엣**: RJ45는 凸 방향 확인 — **스택형은 미러 장착**
   (상단 잭 홈 위, 하단 잭 홈 아래)이 기본, 단독 포트는 홈 아래.
   접점 핀 위치(위/아래), 금속 쉴드 프레임 유무. USB 가로/세로. SFP 클러스터 배열.
5. **표면 텍스처**: 벤트 구멍 모양(원형/사각/육각)·배열(정렬/스태거)·**패치 개수와
   위치 전부** (FortiGate 중앙 벤트 누락 교훈 — 벤트는 세기 쉬워서 빼먹기도 쉽다).
6. **인디케이터**: LED 개수·배열 방향(가로/세로 — DL380 교훈)·라벨 텍스트.
7. **색·재질 단계**: 섀시 톤, 베젤 금속, 포트 내부 파츠는 미묘하게 다른
   명도로 구분(시뮬레이터 가독성 — Ted 팁, FortiGate v3에서 표준화).
8. **관절 후보**: 도어·슬라이드·힌지·트레이 등 움직여야 하는 부분 (KVM 콘솔 패턴).
9. **후면**: 팬 모듈·PSU(개수/블랭크)·인렛·후면 포트 — 자료 있을 때만, 추측 금지.
10. **제외 목록 명시**: 케이블·현장 스티커·케이블타이·벨크로는 프롬프트에
    "ignore ..."로 반드시 명시 (참조 사진에 찍혀 있으면 모델에 스며든다).

## 카테고리별 추가 포커스

- **서버**: 드라이브 베이 수·캐리어 방향(세로)·미디어베이 유무·컨트롤 컬럼 구성.
  Box 구획 균등성. 캐리어는 개별 링크로 명명(drive_bay_NN).
- **스위치/방화벽**: 포트 그룹 경계(그룹 간 seam), 업링크 블록 위치(우측? 중앙? —
  7280SR3 교훈), 콘솔/MGMT 위치(전면인지 후면인지 — 93180YC 교훈).
- **패치패널/액세서리**: 단면 프로파일(평판 vs 채널 vs Z오프셋 — 레이싱 바 2계열 교훈),
  마운트 방식(포스트 직결 vs 브래킷), 타공 수는 실물 카운트 요청.
- **KVM/콘솔**: 관절 2종(슬라이드+힌지) 기본, 닫힘/펼침 두 상태 사진 확보.
- **스토리지**: DPE/DAE 구분 먼저(Unity 교훈), 캐리어 수·그룹핑.

## 프롬프트로 옮길 때

- 치수·무게는 사진이 아니라 **스펙시트/실측**에서 (사진은 비례 검증용).
- 다중 뷰는 합성 시트 1장으로 (≤1200px/~350KB), 각 밴드의 역할을 프롬프트에 설명.
- 물성(총질량 링크 분배 + box 근사 관성)과 동일평면 금지 규칙을 항상 포함.
- 생성 후: audit_grids + audit_coplanar + 질량 합계 검증, 마지막에 사람 육안으로
  **누락**(감사기가 못 잡는 것) 확인.
